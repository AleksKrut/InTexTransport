# Терминалы и датчики

Вход открывает мониторинг. Администратор нажимает «Открыть менеджер», выбирает
клиента и вкладку «Транспорт». Создание и редактирование доступны только там.

## Каталог

В `public/equipment.json` зафиксированы 178 записей моделей из официального
[каталога Traccar](https://www.traccar.org/devices/), проверенного 20.09.2026.
Это выбранные семейства, а не все устройства российского рынка.
Модель выбирается в списке после производителя. Для ручного ввода есть пункт «Другой терминал». Для неизвестной
модели протокол необходимо сверить с документацией производителя.

| Приёмник | Порт TCP |
|---|---:|
| Навтелеком NTCB/FLEX и NAVIS (`navis`) | 5019 |
| Galileosky (`galileo`) | 5034 |
| Неоматика (`adm`) | 5092 |
| Аруснави (`arnavi`) | 5100 |
| Teltonika | 5027 |
| Wialon IPS | 5039 |
| EGTS | 5162 |
| OsmAnd | 5055 |

Реализации новых приёмников и TCP проверены в исходниках Traccar **v6.15.3**:
`src/main/java/org/traccar/protocol/` в
[репозитории Traccar](https://github.com/traccar/traccar/tree/v6.15.3/src/main/java/org/traccar/protocol).
`NavisProtocolDecoder` содержит обработку NTCB и FLEX. Список моделей из каталога
не подтверждает проверку каждой прошивки на настоящем приборе. Не все поля FLEX
обязательно декодируются; датчики, CAN и команды требуют отдельных проверок.
Другие марки и модели добавляются после сверки протокола; это не обещание
поддержки всех моделей Навтелеком или всего рынка.

## Адрес и порт

После обновления запустите `bash install.sh`. Выберите используемые протоколы
и укажите внешний IP или домен рабочего сервера. Для теста только внутри сети
внешний адрес можно оставить пустым. База и учётные записи сохраняются.

Мастер использует тот же каталог, что карточка, и формирует
`.local/connection.json`, который монтируется в веб-контейнер. В файле только
адреса и выбранные протоколы, без паролей. При повторном запуске контейнер
пересоздаётся, чтобы подхватить атомарно заменённый файл.

Карточка показывает состояние **настройки установщиком**, а не результат
проверки соединения снаружи. Проброс портов и firewall на рабочем сервере
настраиваются отдельно. Внешний порт должен соответствовать таблице.
Если конфигурация изменена вручную, сведения установщика также нужно обновить.

На старой установке после одной лишь пересборки сайта адрес будет «не задан»,
а состояние приёмника — неизвестно, пока не выполнен новый мастер.
Выбор модели в карточке не запускает приёмник автоматически.

## Датчики

Во вкладке «Датчики» добавьте название, вид, точное имя параметра и единицу.
После первого сообщения параметры доступны в подсказке и в раскрываемом списке.
До прихода сообщений параметр можно указать вручную по документации протокола.
Поддерживаются числовые, топливные, температурные, дискретные и текстовые показания.

Для чисел применяется `вход × коэффициент + смещение`, затем — необязательная
линейная интерполяция по тарировочной таблице. Каждая строка таблицы имеет вид
`вход;выход`; входы должны строго возрастать. Вне диапазона нет экстраполяции.
Пример: `0;0` и `1000;100` дают 50 литров при входе 500. Пустое или отсутствующее
значение не превращается в ноль. Дискретные значения: true/1 и false/0.

Настройки сохраняются в атрибутах объекта на сервере. Показания видны в мониторинге
при выборе машины, с временем последнего сообщения. Вычисления выполняются
в интерфейсе и не изменяют исходную историю. Настройка физического подключения,
RS-485, CAN, Bluetooth и прошивки выполняется конфигуратором производителя.
Эта версия не добавляет отчёты о сливах/заправках, шаблоны команд, ТО или биллинг.

## Проверки

Браузерные тесты проверяют сохранение модели, SIM и датчиков, выбор порта,
расчёт и восстановление показаний после перезагрузки. Отдельные тесты проверяют
интерполяцию и ошибки тарировки. Серверный smoke-тест проверяет сохранность
настроек датчиков через настоящий API. Приём реального NTCB/FLEX-пакета
в этой задаче не проверялся — для этого нужен терминал и доступ к целевой сети.


## Анализ входящих данных

В открытой карточке на вкладке «Датчики» работает поток `/api/socket` с авторизацией
текущей сессии. Новые расшифрованные параметры появляются автоматически: имя,
исходное значение, предположение о назначении и время последнего получения.
При обрыве выполняется повторное подключение; резервный REST-опрос — каждые 5 секунд.
В мониторинге показания выбранного объекта тоже получают обновления из потока.

Если поле отсутствует в следующем сообщении, оно остаётся в диагностическом списке
с отметкой отсутствия, без подстановки нуля. Рабочий список (до 512 полей) хранится
пока открыта карточка; после её закрытия диагностика начинается с последнего сообщения.
Сами сообщения сохраняет Traccar независимо от открытой страницы. Это не отдельный
постоянный серверный реестр датчиков. Незавершённые настройки датчиков не меняются
от входящих сообщений. «Создать датчик» заполняет форму, а запись на сервер
выполняется общей кнопкой «Сохранить».

Определение идёт по стандартным именам параметров, не по физической модели датчика.
Для неизвестных полей и аналоговых входов назначение и единицы задаются вручную;
по одному `adc1` нельзя определить топливо, модель ДУТ и тарировочную таблицу.
Нерасшифрованные серверным обработчиком байты здесь не анализируются.
