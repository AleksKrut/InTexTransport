# Мастер установки

На Ubuntu Server 22.04, 24.04 или 26.04 LTS, архитектура amd64/arm64:

```bash
git clone https://github.com/AleksKrut/InTexTransport.git monitoring-local
cd monitoring-local
bash install.sh
```

Для самого `git clone` уже нужен Git. Если его нет:
`sudo apt update && sudo apt install -y git`.
Далее мастер сам устанавливает отсутствующие базовые зависимости и Docker.
Нужны SSH с интерактивным терминалом, sudo/root и доступ в интернет для пакетов/образов.
Установка не требует Node.js, pnpm или Python-библиотек на сервере.

## Что спросит мастер

1. Постоянный IPv4 интерфейса сервера. Адреса определяются автоматически, выбор подтверждает пользователь.
2. Порт сайта (по умолчанию 8080).
3. Протоколы терминалов: OsmAnd, Teltonika TCP, Wialon IPS TCP, EGTS TCP.
4. Внешний IP или полное DNS-имя для терминалов — необязательно.
5. Подтверждение установки.
6. Имя, email и пароль первого администратора, если пользователей ещё нет.

Мастер проверяет Ubuntu и архитектуру, устанавливает недостающие пакеты из APT,
использует официальный репозиторий Docker при новой установке. Существующий Docker
не заменяет автоматически; для Docker CE и Ubuntu docker.io пробует добавить только
недостающие Compose/Buildx. При конфликтующих или нестандартных установках прекращает
работу с пояснением, не удаляя чужие контейнерные пакеты.

Требуется Compose >= 2.24.4. Мастер не обновляет автоматически старую установленную
версию Compose и не выполняет полное обновление ОС.
Проверяется наличие не менее 5 ГБ свободного места **в каталоге проекта**; это лишь
порог для старта, не расчёт места под телеметрию. Docker может хранить данные на
другом разделе — проверьте свободное место и там.

## Что делает автоматически

- Создаёт .env со случайным паролем базы (если файла ещё нет).
- Генерирует compose.override.yaml с выбранными портами.
- Сначала запускает сайт и протоколы только на loopback.
- Скачивает Docker-образы, собирает интерфейс и ждёт готовности сервисов.
- Создаёт первого администратора через локальный API, проверяет вход.
- Проверяет, что открытая регистрация выключена.
- Открывает сервисы на выбранном LAN-интерфейсе и проверяет ответ API через сайт.
- Печатает адрес сайта, адреса/порты терминалов, подсказки по DNS/NAT.
- Сохраняет памятку в .local/installation.txt.

Пароль администратора вводится скрыто, не выводится в итоговую памятку и не сохраняется
мастером в файлы. PostgreSQL и Traccar сохраняют необходимые учётные данные штатным способом.
Пароль БД находится только в локальном .env (не в Git).

После установки: откройте выданный адрес сайта, войдите и выберите «Мониторинг»
или «Менеджер». Добавьте транспорт по его настоящему ID/IMEI и назначьте клиентам.

## Повторный запуск

`bash install.sh` повторно предлагает прежние настройки, сохраняет базу,
пароль PostgreSQL и существующие учётные записи. На время проверки администратора
доступ из LAN кратковременно закрывается; это не фоновое обновление без простоя.
При обрыве запуска повторите ту же команду. Мастер не удаляет Docker-тома.

Чужой compose.override.yaml не перезаписывается. Предыдущие версии файла,
созданного мастером, сохраняются в .local/compose-previous-*.yaml.
Состояние мастера хранится в .local/install-state.json.
Эти файлы и .env не должны попадать в GitHub.

Мастер работает через sudo. Для дальнейшего обслуживания используйте:
`sudo docker compose ...`, `sudo bash scripts/backup.sh`.
Чтение памятки: `sudo cat .local/installation.txt`.
Мастер не добавляет пользователя в привилегированную группу docker.
Параметры сети после установки задаются в compose.override.yaml; изменения
WEB_BIND/TRACKER_BIND в .env не перекрывают этот файл. Проще повторить мастер.

## DNS, интернет и терминалы

Мастер не покупает домен, не создаёт DNS-записи у провайдера, не меняет роутер
и не назначает статический IP операционной системе. Для этого нужны доступы
к соответствующим устройствам/аккаунтам.

Если указан домен, проверяется его текущее разрешение в IPv4. Это не проверка
доступности порта из мобильной сети. Для внешнего подключения:
создайте DNS A-запись на публичный IP, направьте нужные порты на LAN-IP сервера
или используйте VPN/частный APN. При CGNAT обычный проброс портов не поможет.

Мастер выдаёт отдельную пару «адрес + порт» для каждого выбранного протокола.
Нельзя направлять любой трекер на произвольный порт: проверьте точную модель
в [списке Traccar](https://www.traccar.org/devices/). Пресеты мастера используют TCP.
Другие протоколы/UDP можно добавить отдельно в конфигурацию.

Сайт пока HTTP для доверенной LAN; HTTPS и публикация клиентского портала —
отдельный этап. Мастер не открывает UFW и не меняет firewall:
Docker-порты могут обходить UFW, поэтому фильтрацию нужно проверить отдельно.
Карты по умолчанию загружаются из OpenStreetMap; автономные карты мастер не скачивает.
