# Обновление и восстановление

После установки мастером команды Docker и скрипты обслуживания выполняйте
через sudo: локальные конфигурационные файлы принадлежат root.
Сеть и порты мастера находятся в compose.override.yaml. Сохраняйте его
вместе с .env и .local/install-state.json при переносе сервера.

## Обновление

1. Создайте бэкап: `bash scripts/backup.sh`.
2. Запишите текущий коммит: `git rev-parse HEAD`.
3. Проверьте локальные изменения: `git status`.
4. Выполните `git pull --ff-only`.
5. Выполните `docker compose up -d --build --wait --wait-timeout 300`.
6. Проверьте `bash scripts/check.sh`, вход, список и реальные координаты.

Не меняйте основную версию PostgreSQL простым переключением тега.
Для major upgrade нужен отдельный план миграции/переноса базы.
Traccar зафиксирован на 6.15.3. Перед обновлением проверяйте миграции на копии базы.
Образы PostgreSQL 17 и Nginx stable получают обновления в пределах своих тегов;
для полностью неизменяемого выпуска закрепите проверенные digest всех образов.
`docker compose pull` обновляет внешние образы только по вашему явному запуску.

При смене пароля в .env существующая PostgreSQL не меняет пароль роли автоматически.
Нужно отдельно изменить пароль в БД и согласованно обновить .env.

## Восстановление SQL-бэкапа

Сначала восстановите копию на отдельном сервере. Следующие действия заменяют
данные существующей базы; используйте их только при намеренном восстановлении.

Сохраните текущую базу, если она доступна. Остановите сервисы записи:

```bash
docker compose stop web traccar
docker compose up -d db
docker compose exec -T db pg_isready -U monitoring -d monitoring
```

Восстановите выбранный дамп (замените имя файла на реальное):

```bash
docker compose exec -T db pg_restore -U monitoring -d monitoring \
  --clean --if-exists --no-owner --no-privileges --single-transaction \
  < backups/database-YYYYMMDDTHHMMSSZ.dump
docker compose up -d --wait --wait-timeout 300
bash scripts/check.sh
```

Используйте версию Traccar, соответствующую бэкапу, и совместимую PostgreSQL.
Проверьте вход, количество устройств и маршруты. Пустую базу сначала восстановите,
а уже затем запускайте Traccar — так миграции выполнятся в правильном порядке.

## Штатный интерфейс Traccar

Для расширенных настроек, геозон, отчётов и пользователей:

```bash
ssh -N -L 8082:127.0.0.1:8082 USER@SERVER_IP
```

Откройте `http://localhost:8082`. Учётные записи и данные те же.
Порт 8082 по умолчанию никогда не публикуется в LAN.
Не открывайте регистрацию при работе с несколькими клиентами.

## Диагностика

- Нет сайта: `docker compose ps` и `docker compose logs --tail 100 web`.
- Traccar unhealthy: посмотрите `docker compose logs --tail 150 traccar`;
  проверьте пароль, доступность PostgreSQL и корректность XML.
- Нет координат: проверьте модель/протокол, IMEI, APN, порт и доступность сервера.
- Нет карты, но список работает: проверьте источник тайлов и WebGL браузера.
- Маршрут слишком большой: сократите период; сервер ограничивает число точек.
- Диск заполняется: контролируйте `df -h`, объём базы и резервных копий.
- После пересоздания Traccar перезапустите web, если Nginx продолжает отдавать 502:
  `docker compose restart web`.

Метрики нагрузки, автоматическое расписание резервных копий, срок хранения
телеметрии и внешние оповещения нужно настроить под реальный парк перед эксплуатацией.
