# ИнТехТранспорт

Первая версия локальной системы мониторинга транспорта. Собственный русскоязычный
веб-интерфейс на React и TypeScript, приём данных и API — Traccar, хранилище — PostgreSQL.
Установка на Ubuntu Server через Docker Compose. Это начало самостоятельного продукта,
а не полный аналог Wialon и не его исходный код.

## Что работает в этой версии

- Создание первого администратора, вход и выход через сессионные cookie.
- Все пользователи входят сразу в мониторинг. Администратору доступна кнопка «Открыть менеджер».
- Обычный пользователь сразу попадает в наблюдение за назначенными объектами, без выбора разделов.
- Менеджер: список клиентов слева, вкладки «Клиенты», «Пользователи», «Транспорт»,
  таблицы с поиском и страницами, отдельные формы создания и редактирования.
- Создание менеджеров системы с полным доступом и наблюдателей только для просмотра.
- Карточка транспорта: каталог моделей и протоколов, параметры подключения, две SIM, подразделение, VIN, прошивка, датчики и тарировка.
- Клиенты получают доступ только к назначенному транспорту, без изменения объектов и команд.
- Добавление транспорта по имени и идентификатору трекера.
- Карта, поиск транспорта, последние координаты, скорость, зажигание и время связи.
- Обновление списка и позиций каждые 5 секунд; при сбое виден статус ошибки.
- Маршрут за выбранный период до 7 дней (максимум 50 000 точек на запрос).
- Постоянные Docker-тома для базы и данных Traccar.
- Генерация пароля базы, резервное копирование и тестовый отправитель координат.
- GitHub Actions: сборка, проверки и сквозной тест с реальным сервером в контейнере.

Биллинг, собственные отчёты о стоянках и топливе, иерархия организаций
и уведомления пока не реализованы в нашем интерфейсе.
В первой версии клиент — отдельная учётная запись; одна машина может быть назначена
нескольким клиентам явно. Это не жёсткая модель владения транспортом организацией.
Расширенные функции Traccar доступны в его штатном интерфейсе через SSH-туннель.
Отдельный NestJS-сервис в первой версии не используется: сайт обращается к API
Traccar через Nginx, а права проверяются Traccar на сервере.

## Быстрая установка с мастером

На Ubuntu Server после клонирования репозитория:

```bash
cd monitoring-local
bash install.sh
```

Мастер проверит зависимости, установит недостающее, предложит IP и протоколы
терминалов, создаст администратора и запустит сервисы. В конце выдаст адрес сайта
и таблицу подключения терминалов. Повторный запуск сохраняет данные и пароли.
Нужны sudo и интернет. DNS-записи и проброс портов на роутере настраиваются отдельно.
Подробности: [мастер установки](docs/installer.md).

## Ручная установка на Ubuntu

Нужны Git, Python 3, Docker Engine и Docker Compose plugin.
Docker установите по [официальной инструкции](https://docs.docker.com/engine/install/ubuntu/).
Команды ниже предполагают, что текущему пользователю уже разрешён доступ к Docker.
Для пилота можно начать с 4 ядер, 8 ГБ RAM и SSD; это ориентир, не расчёт ёмкости.
Размер диска под историю рассчитывается отдельно по числу устройств и частоте точек.

После загрузки проекта в **свой** GitHub-репозиторий:

```bash
git clone https://github.com/AleksKrut/InTexTransport.git monitoring-local
cd monitoring-local
python3 scripts/configure.py
docker compose up -d --build --wait --wait-timeout 300
bash scripts/check.sh
```

Замените адрес репозитория на свой. При первом запуске нужны интернет для скачивания
Docker-образов и npm-пакетов. Сборка интерфейса выполняется внутри Docker, Node.js
на Ubuntu устанавливать не нужно. .env не перезаписывается повторной настройкой.

### Первый вход

Первоначально сайт слушает только `127.0.0.1:8080` сервера, чтобы первая
учётная запись администратора не досталась случайному посетителю.

На своём компьютере создайте SSH-туннель (подставьте пользователя и адрес сервера):

```bash
ssh -N -L 8080:127.0.0.1:8080 USER@SERVER_IP
```

Откройте `http://localhost:8080` в браузере. Создайте администратора с паролем
не короче 12 символов. Первая учётная запись получает права администратора.
Открытая регистрация после первого пользователя по умолчанию отключена.

Все пользователи входят сразу в мониторинг. Администратору доступна кнопка «Открыть менеджер».
В менеджере на вкладке «Клиенты» создайте клиента и задайте первоначальный пароль.
На вкладке «Транспорт» нажмите «Добавить транспорт» и выберите клиента для назначения.
Для дополнительных сотрудников используйте вкладку «Пользователи».
Выберите строку клиента или наблюдателя и нажмите «Доступ к транспорту» для изменения
доступных машин. Изменения сохраняются сразу. В отдельном приватном окне войдите
под клиентом и проверьте, что видны только назначенные объекты. Клиенту раздел
менеджера не показывается; сервер также ограничивает доступ к чужим данным.

### Доступ в локальной сети

После создания администратора измените в `.env`:

```dotenv
WEB_BIND=192.168.1.50
TRACKER_BIND=192.168.1.50
```

Здесь `192.168.1.50` — пример: укажите постоянный LAN-адрес **вашего сервера**.
Примените настройки:

```bash
docker compose up -d --wait --wait-timeout 300
```

Открывайте `http://192.168.1.50:8080` с компьютеров этой сети.
На данном этапе HTTP предназначен для доверенной локальной сети или SSH-туннеля.
Перед доступом клиентов через интернет нужны HTTPS, выбранная схема доступа
и проверка разграничения прав. База данных не публикует порт на хост.

Docker-порты могут обходить правила UFW. Ограничивайте доступ также на маршрутизаторе
и средствами фильтрации Docker; не полагайтесь только на `ufw deny`.

## Проверка без оборудования

В «Менеджер» → «Транспорт» добавьте «Тестовый автомобиль» с идентификатором `demo-001`.
Пока TRACKER_BIND оставлен по умолчанию, на сервере выполните:

```bash
python3 scripts/simulate.py --id demo-001
```

Если TRACKER_BIND уже изменён на LAN-адрес:

```bash
python3 scripts/simulate.py --url http://192.168.1.50:5055 --id demo-001
```

Тестовые точки появятся около Екатеринбурга. Это явно синтетический маршрут,
а не данные реальной машины. Выберите транспорт, укажите период с текущим временем
и нажмите «Показать маршрут». Не используйте идентификатор реального устройства для теста.

## Реальные трекеры

В базовой конфигурации открыт **только OsmAnd TCP/HTTP 5055** для проверки.
Не назначайте этот порт произвольному трекеру: протоколы оборудования различаются.

1. Найдите точную модель в [списке устройств Traccar](https://www.traccar.org/devices/).
2. Укажите нужный `<entry key="PROTOCOL.port">PORT</entry>` в `infra/traccar.xml`.
3. Добавьте соответствующий TCP и/или UDP порт в `traccar.ports` файла Compose.
4. Пересоздайте сервис: `docker compose up -d --force-recreate traccar web`.
5. В трекере настройте APN, адрес сервера и порт; добавьте его идентификатор в сайт.

Для транспорта вне вашей сети нужен достижимый адрес: публичный IP и проброс
только необходимых портов либо VPN/частный APN. Доступность сайта в интернете
не требуется для приёма телеметрии. Настройки конкретного оборудования выбираются
после уточнения модели. Защищённость протокола зависит от устройства; IMEI сам по себе
не является надёжным секретом.

## Карты и внешний доступ

По умолчанию браузер запрашивает растровые тайлы OpenStreetMap.
Соблюдайте [политику сервиса](https://operations.osmfoundation.org/policies/tiles/):
атрибуция обязательна, массовое скачивание и офлайн-загрузка не допускаются.
Провайдер видит IP браузера и запрашиваемую область карты.
Для автономного режима или большого парка подключите свой источник карт.

Измените `public/config.json`: название, начальный центр `[долгота, широта]`,
масштаб, URL тайлов и атрибуцию. Затем `docker compose up -d --build web`.
Ключи поставщика карт в этом файле видны браузеру — используйте только публичные
ограниченные ключи. Телеметрия хранится в вашей PostgreSQL; внешняя аналитика
Traccar отключена в конфигурации.

## Обслуживание

```bash
docker compose ps
docker compose logs --tail 100 traccar
bash scripts/backup.sh
```

Копируйте резервные копии на отдельный носитель. Вместе с базой сохраняйте `.env`,
свои изменения конфигурации и идентификатор коммита. Файлы логов и загруженные
файлы тома traccar-data не включены в SQL-бэкап; если используете вложения,
резервируйте этот том отдельно.

Обновление и восстановление описаны в [docs/operations.md](docs/operations.md).
Не выполняйте `docker compose down -v`: эта команда удаляет данные томов.
Автоматическое удаление старой телеметрии пока не настроено — контролируйте диск.

## Разработка и проверки

Инструкция по клиентам, транспорту и правам: [Работа в менеджере](docs/manager.md).

Нужны Node.js 24 и pnpm 11.19.0. Зависимости зафиксированы в `pnpm-lock.yaml`.

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm exec playwright test
docker compose up -d db traccar
pnpm dev
```

Vite проксирует API на `127.0.0.1:8082`.
Для полноценной проверки на **новой одноразовой базе**:
`python3 scripts/smoke.py`. Скрипт отказывается работать, если пользователь
уже существует. Он создаёт администратора и тестовые точки — не запускайте его
на рабочем сервере. GitHub Actions запускает его в изолированном окружении.

## Структура

- `src/` — собственный интерфейс React, карта MapLibre и клиент API.
- `infra/` — Nginx и настройки Traccar.
- `scripts/` — настройка, тестовые координаты, бэкап и диагностика.
- `tests/` — проверки обработки координат, единиц скорости и периода.
- `.github/workflows/` — автоматические проверки при push и pull request.

## Загрузка на GitHub

Создайте пустой репозиторий в своём аккаунте, без автоматически добавленного README.
В папке проекта выполните:

```bash
git add .
git commit -m "Initial local monitoring platform"
git branch -M main
git remote add origin https://github.com/AleksKrut/InTexTransport.git
git push -u origin main
```

Если origin уже существует, проверьте его через `git remote -v`.
Не публикуйте `.env`, дампы базы и реальные данные клиентов: они исключены в .gitignore.

Компоненты имеют собственные лицензии; см. [THIRD_PARTY.md](THIRD_PARTY.md).

Подробнее: [Терминалы, подключение и датчики](docs/equipment.md).
